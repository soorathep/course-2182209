# Manual archive for Chemistry for Semiconductor Engineering (2182209)

The course owner starts each Zenodo archive manually. When preparing an edition, make a private review copy of the materials taught that academic year. Record the academic year, edition, preparation date, GitHub Pages URL and exact source commit. Record the deployed Sites version and source commit for the 14 pre-midterm classes. Use the teaching record to identify the edition. A repository or build date alone does not establish the academic year.

## Assemble the snapshot

- Start with an explicit file inventory covering the syllabus, all 14 English lessons and exit-ticket questions, simulation demos, prepared datasets, worksheets and student workbook. Include editable sources, figure generators, the dependencies needed to rebuild the release, and rendered files. Add a README with entry points, build instructions and offline limitations. Record any material taught elsewhere as outside the scope of the 14-class collection.
- Check the site and teaching files for linked videos, captions, downloads, references and legacy skhgroup.net assets. For dependencies required to use a lesson, include the rights-cleared payload and record its source URL, version, credit and SHA-256. Document missing assets and the resulting gap. Obtain permission or agree on a documented omission before publication.
- The hosted exit tickets accept a self-entered name and student ID without student login. Preserve the public questions and form definitions. Document the hosted service and include reviewed, redistributable backend source, an empty schema and instructions for testing with synthetic records when needed to reproduce the behavior. Run offline copies against an isolated test service or disable submission in the archive. An archived form must not submit to the live class.
- Keep the instructor guide, answer keys, instructor-only source payloads and server configuration under their existing access controls. Identify their version and restricted location in a **private** preservation inventory. Review backend source and generated bundles for embedded private material before adding them to a public package. Exclude live or exported responses, session records, class lists, grades, feedback text, databases, credentials and private access settings from the deposit.

## Check privacy, rights and integrity

1. Inspect filenames, document properties, comments and tracked changes, hidden sheets, image metadata, screenshots, free text and generated assets for personal data and confidential assessment material. Record findings and corrections in a private review receipt. Make reviewed copies without altering originals.
2. Prepare credits and a rights inventory for each third-party item, including excerpts, figures, media, fonts, data and software. Record creator, source, license or permission evidence, required attribution and restrictions. Resolve uncertain rights before public release.
3. Draft Zenodo metadata with the title, academic year and version, creators, affiliations, confirmed ORCIDs if available, description, resource type, language, keywords, dates, approved license or access terms, and links to the exact repository revision and course URL.
4. Record relative paths, byte sizes and SHA-256 digests for the payload. Include a sorted `SHA256SUMS` manifest excluding itself. Extract the finished package into a clean directory, verify every hash, open all 14 lessons, run the demos and check downloads and necessary media. Record external dependencies and offline limitations. Compute a separate SHA-256 for the final archive file.

## Approval and version DOI

Present the exact package, archive checksum, metadata, credits, privacy and rights findings, exclusions and test results to the course owner. Obtain approval before uploading or publishing to Zenodo. After publication, resolve the **version-specific DOI**, confirm the academic year and version on its record, download the deposited package and compare its SHA-256 with the approved file. Then add the verified DOI to the course website with its academic year and edition. Keep the receipt with the source commits, checksum and verification date.

Keep earlier materials, pages and media available. Any removal or redirect requires a separate impact check and owner approval.
